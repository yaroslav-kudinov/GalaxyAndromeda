# ADR 014: Чат комнаты (общий и личный)

## Status

Accepted

## Context

Игрокам нужна переписка в комнате подготовки и во время партии. Главное меню (landing) чат не требует. Синхронизация партии уже идёт через HTTP-опрос состояния; WebSocket `/api/ws` — заглушка echo.

## Decision

- Чат только для участников комнаты (`playerIds`): лобби и `playing`.
- HTTP-контракт (не observation):
  - `GET /api/rooms/:id/chat?playerId=&after=` → `{ messages: RoomChatMessage[] }`
  - `POST /api/rooms/:id/chat` body `{ playerId, text, toPlayerId? }` → `{ message }`
- Сообщение: `{ id, at, fromPlayerId, fromName, toPlayerId | null, text }`. `toPlayerId: null` — общий канал; иначе личное (видно отправителю и получателю).
- Хранение: in-memory на процесс сервера, история до 200 сообщений на комнату; очищается при уничтожении комнаты. Не пишется в `.dev-rooms` / SQLite.
- Безопасность: длина текста ≤ 400; частота ≤ 12 сообщений / минуту на игрока; без HTML-разметки на сервере (клиент рендерит текст как текст); получатель DM должен быть в комнате.
- UI: сворачиваемая панель в комнате игры; не на landing.

## Consequences

- Клиент опрашивает чат отдельно от observation (реже, например 1.5–2 с).
- При рестарте сервера история чата теряется — приемлемо для текущего масштаба.
- Полный WS-push чата можно добавить позже без смены полей сообщения.
