# ADR 011: Маркеры действия = два плюс центры власти, лимит замораживается в начале хода

## Status

Accepted

## Context

ADR 010 приравнял лимит маркеров действия к числу контролируемых центров власти и пересчитывал его сразу при смене контроля. Это ломало старт (один центр давал один маркер вместо привычных трёх) и наказывало за потерю центра в середине хода: маркеры снимались, пока ещё шла фаза действий.

`types.ts` не меняется. Поле snapshot `actionMarkerLimitByPlayer` переиспользуется как **замороженное** значение на игровой ход.

## Decision

- Формула: `actionMarkerLimitByPlayer[playerId] = 2 + n`, где `n` — число клеток `isPowerCenter` с `controlOwnerId === playerId`.
- Старт партии: у каждого игрока один центр власти → **3** маркера действия. Покупка маркеров действия по-прежнему запрещена.
- Пересчёт **только** в начале игрового хода: после производства, когда карта события применена и фаза становится «Планирование» (`completeEventsPhaseIfActive` / `advanceGameSnapshot` при входе в planning), плюс `beginMatchForParticipants`.
- Бой, объявление контроля и смена контроля в середине хода **не** вызывают `refreshActionMarkerCapacity`. Пока ход не закончился, для постановки маркеров действует замороженный лимит.
- Если к началу хода на карте больше маркеров, чем новый лимит, лишние снимаются детерминированно (сортировка q, r, id; остаются первые `limit`).
- Выбытие за потерю всех центров власти по-прежнему снимает маркеры выбывшего (как сдача), отдельно от обрезки по лимиту.

Observation отдаёт хранимый `actionMarkerLimitByPlayer`, а не живой пересчёт по центрам.

## Consequences

- Клиент: справка и шапка партии — «два плюс число центров власти», пересчёт в начале хода.
- Старые сейвы: если поле уже записано (старая формула «равно числу центров»), оно держится до следующего начала хода, затем становится `2 + n`. Если поля нет — при загрузке заполняется `2 + n` без обрезки до начала хода.
- Print-and-play не обновляли.
