# ADR 006: Колода карт событий

## Status

Accepted

## Context

Раньше вытягивание события было либо детерминированным по номеру хода, либо независимым полным рандомом (`Math.random` по списку из 14 id). Нужна модель «колоды»: карты перемешиваются, снимаются сверху, при опустошении колода собирается заново. Самые жёсткие эффекты должны встречаться реже.

## Decision

В `GameSnapshot` добавить поле:

```typescript
eventDeck?: EventCardId[] // оставшиеся карты; верх = индекс 0
```

Состав полной колоды задаётся `EVENT_DECK_COPIES` в `events.ts` (копии карт). Жёсткие карты — 1 копия; средние — 2; мягкие/полезные — 2–3.

При входе в фазу «События» `ensureTurnEventForPhase` вызывает `drawNextEventFromDeck`: если колоды нет или она пуста — `createShuffledEventDeck`, затем `shift()`. Поле синхронизируется через observation (`eventDeck`).

## Consequences

- Старые сохранения без `eventDeck` получают новую колоду при первой вытяжке.
- Клиент/агенты видят остаток колоды в observation (можно считать карты — как в настольной игре).
- `drawTurnEvent(turnNumber)` устарел и не используется игровым циклом.
