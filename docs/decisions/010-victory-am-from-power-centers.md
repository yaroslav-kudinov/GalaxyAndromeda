# ADR 010: Победа без 4×7, маркеры действия от центров власти

## Status

Accepted

## Context

Победа «4 связных региона по ≥7 клеток» дублировала территориальный контроль и плохо читалась за столом. Маркеры действия покупались в производстве (старт 3, потолок 8, цена 6+6 и +2/+2) — отдельная экономика, не связанная с центрами власти.

`types.ts` не меняется. Поля snapshot `actionMarkerLimitByPlayer` и `gameOver.reason` переиспользуются.

## Decision

### Победа

`checkVictory` / `gameOver.reason`:

- `power_centers` — строго больше половины **всех** центров власти на карте;
- `last_standing` — единственный невыбывший (включая сдачу).

`four_regions` больше не выставляется. Старые сейвы с этим reason только отображаются как неизвестная строка.

### Маркеры действия

См. [ADR 011](./011-action-markers-two-plus-centers.md): формула **2 + n** и пересчёт только в начале хода. Ниже — решение на 2026-08-24 (устарело).

`actionMarkerLimitByPlayer[playerId]` = число клеток `isPowerCenter` с `controlOwnerId === playerId`.

- Старт партии: столько AM, сколько PC на setup. 0 PC → 0 AM, пока не захвачен центр.
- Покупка AM (`buyActionMarkers`, цены, лимит 8) удалена. `execute-production` с `buyActionMarkers > 0` — ошибка.
- Лимит живой: захват PC в планировании сразу даёт слот; в действиях/производстве слот доступен со следующего планирования.
- Потеря PC: лимит падает; лишние AM снимаются с карты детерминированно (сортировка q, r, id; остаются первые `limit`). Ход фазы не тратится.
- Событие `production-accident` запрещает только покупку **маркеров производства**.

Observation по-прежнему отдаёт `actionMarkerLimitByPlayer` (теперь PC-count, не купленный пул).

## Consequences

- Клиент: ProductionModal без покупки AM; справка и HUD считают слоты по центрам власти.
- Протокол: `buyActionMarkers` убран из `execute-production`.
- Старые сейвы: купленный пул AM игнорируется; при загрузке лишние маркеры снимаются.
- Print-and-play не обновляли.
