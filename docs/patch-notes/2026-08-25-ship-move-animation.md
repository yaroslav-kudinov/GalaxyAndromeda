# Корабли на карте коротко пролетают к новой клетке после хода

Дата: 2026-08-25
Ветка: agent/debug-combat-markers-ui

## Суть

Когда корабль уже перешёл на другую клетку по правилам, значок на карте больше не телепортируется: он примерно за половину секунды пролетает от прежней клетки к новой. Это только картинка. Ходы, бой и очередь обстрела идут как раньше, без ожидания окончания полёта.

Если корабли ещё стоят на исходной клетке, потому что начался бой, полёта нет. После того как бой закончится и флот действительно окажется на клетке назначения, значок пролетает этот последний отрезок.

## Правила

Правила игры не менялись.

## Код

Для разработчиков: только клиент `@galaxy/client`. Сравнение клеток по идентификатору корабля — `utils/ship-move-index.ts`. Косметический полёт — `composables/useShipMoveTweens.ts` (`SHIP_MOVE_TWEEN_MS`: было 320 мс, стало 500 мс; новый снимок обрывает текущий полёт). Слой глифов в `HexBoard.vue`: пока значок летит, на клетке назначения он скрыт, рисуется отдельный слой поверх; клики по-прежнему по гексу, не по глифу. Действие на сервер не откладывается, `pendingCombat` и список легальных действий не читают позицию полёта. Полупрозрачные клетки и фон космоса не трогались.

## API / контракт

Контракт для программ не менялся.

## UI

После мирного хода значки кораблей примерно за половину секунды пролетают к новой клетке. Пока идёт бой и корабли по правилам ещё на исходной клетке, они остаются на месте. Сменилась ориентация карты — полёт обрывается, значки сразу на актуальных клетках. Редактор карты без полёта.

## Тесты

Проверка сравнения клеток: `pnpm --filter @galaxy/client test`. Вручную: ход без боя — значок летит, панель и подсказка клетки сразу показывают новый состав; вход в бой — на исходной клетке до конца боя, затем полёт на назначение; чужой ход с опросом комнаты не должен дёргать значок, пока клетка не сменилась.

Миграция сохранений не нужна.
