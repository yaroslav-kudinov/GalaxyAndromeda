# Маркеров действия снова три на старте: два плюс число ваших центров власти

Дата: 2026-08-25
Ветка: agent/debug-combat-markers-ui

## Суть

Число маркеров действия снова считается как два плюс сколько центров власти вы контролируете. На старте у каждого один центр власти — значит три маркера, как раньше, без покупки.

Лимит больше не прыгает в середине хода. Потеряли центр власти в бою — маркеры с карты сразу не снимают. Заняли новый центр в планировании — четвёртый маркер появится только со следующего хода.

## Правила

Раньше лимит был равен числу ваших центров власти один к одному: один центр — один маркер. Потеря центра сразу убирала лишний маркер с карты, а новый центр в планировании сразу давал ещё один.

Теперь доступно два плюс число ваших центров власти. Пересчёт только в начале игрового хода: после производства, когда карта события уже применена и начинается планирование. До этого момента действует число, записанное в начале текущего хода.

Если к началу нового хода маркеров на карте больше, чем позволяет новый лимит, лишние снимаются однозначно (остаются те, что с меньшими координатами). Поставить больше замороженного лимита в текущем ходе нельзя.

Покупка маркеров действия по-прежнему недоступна. Маркеры производства не менялись.

Выбытие за потерю всех центров власти по-прежнему снимает маркеры выбывшего игрока, как при сдаче.

## Код

Для разработчиков: пакет правил — `marker-pools.ts` (формула `2 + n`, `actionMarkerLimitForPlayer` читает замороженное поле), `turn.ts` (`completeEventsPhaseIfActive` и вход в планирование), `match-start.ts`. Убраны вызовы `refreshActionMarkerCapacity` из боя, объявления контроля, проверки победы и списка допустимых действий. Клиент: справка, подсказка планирования, подпись счётчика в шапке партии. Решение: `docs/decisions/011-action-markers-two-plus-centers.md`.

## API / контракт

Для разработчиков: поле `actionMarkerLimitByPlayer` то же; это лимит на текущий ход, а не живое число центров. Наблюдение отдаёт хранимое значение. Покупка маркеров действия по-прежнему отклоняется.

## UI

В шапке партии счётчик маркеров действия подписан как «два плюс число центров власти на начало хода». Справка и подсказка планирования говорят ту же формулу и что пересчёт — в начале хода, а не сразу после потери или захвата центра.

## Тесты

Автоматические проверки: один центр власти на старте даёт три маркера; два центра в начале хода дают четыре; потеря центра в середине хода не меняет лимит и не снимает маркеры; в начале следующего хода лишние снимаются; захват центра в планировании не даёт четвёртый маркер до пересчёта. Запуск пакета правил: `pnpm --filter @galaxy/rules test`.

## Миграции

Старые сохранения, где лимит уже записан по прежней формуле «столько, сколько центров», держат это число до начала следующего хода, затем получают два плюс текущие центры. Если поля нет, при загрузке его заполняют по новой формуле, но лишние маркеры с карты не снимают, пока не начнётся новый ход. Бумажную версию для печати не меняли.
