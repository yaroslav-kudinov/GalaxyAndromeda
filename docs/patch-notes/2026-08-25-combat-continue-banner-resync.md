# После раунда боя «продолжить или отступить» появляется сразу, без обновления страницы

Дата: 2026-08-25
Ветка: agent/debug-combat-markers-ui

## Суть

После раунда боя стороне, которой пора решать — продолжать сражение или отступить, — кнопки иногда не показывались, пока человек не обновлял страницу. На сервере очередь уже была правильная: после обновления кнопки сразу были на месте. Особенно это било по игроку, который уже закрыл окно итога раунда и ждал своей очереди (часто защитник, когда атакующий уже выбрал продолжить, или атакующий после того, как победитель подтвердил потери).

Теперь решение видно на следующем снимке комнаты: закрыли итог — баннер с кнопками появляется сразу. Чужой бой при закрытом окне тоже больше не оставляет пустой экран.

## Правила

Правила игры не менялись. По-прежнему сначала решает атакующий, затем защитник. Пока в этом бою никто не уничтожен, отступление недоступно, обе стороны только подтверждают продолжение.

## Код

Для разработчиков: клиент `@galaxy/client`. Логика очереди и баннера вынесена в `utils/combat-continue-ui.ts`. Закрытие итога запоминает броски раунда (`combatResultRollsKey`), а не полный отпечаток результата: после подтверждения уничтожения отпечаток меняется, броски те же — окно не открывается снова и не прячет баннер. Баннер «продолжить или отступить» завязан на роль в бою и на то, закрыто ли окно, а не на «чей ход на карте». Статус чужого боя показывается, если окно итога не на экране. Сервер и пакет правил не менялись.

## API / контракт

Контракт для программ не менялся.

## UI

После закрытия итога раунда игрок, чья очередь решать, сразу видит кнопки «Продолжить бой» и при необходимости «Отступить». Не нужно обновлять страницу. Пока очередь чужая, видна подсказка, кто сейчас выбирает. Окно итога по-прежнему можно снова открыть кнопкой «Показать итог».

## Тесты

Автоматические проверки в клиенте: очередь атакующего затем защитника; защитник не смотрит на ход на карте; баннер при закрытом окне даже если итог формально «не просмотрен»; закрытие сохраняется, когда после уничтожения меняется только состав потерь, и сбрасывается на новых бросках следующего раунда. Запуск: `pnpm --filter @galaxy/client test`. Вручную: два клиента, бой с потерями, закрыть итог на стороне, которая не выбирала уничтожение, подтвердить потери, затем продолжить атакующим — у защитника кнопки без обновления страницы.
