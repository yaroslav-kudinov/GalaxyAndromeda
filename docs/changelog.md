# Changelog

## [Unreleased]

### Added

- **Щитоносец:** поглощение усилено до 6 на клетке / 3 с соседа (было 4/2).
- **Авианосец:** аура своим кораблям в бою (+1d6 на клетке / +1d4 с соседа; не стакается; не на авианосцы). Цена 6+5, регион от 12, лимит 3.
- **Маркер на центр власти:** можно ставить маркер действия на свой центр власти без корабля — для постройки.
- **Закрытие комнаты:** создатель может закрыть комнату подготовки; после победы комната удаляется через 30 секунд.
- **Политика CI/CD:** деплой production-сборки только по явной команде; `docs/cicd-deploy-policy.md`, `harness/README.md`.
- **Перезарядка фишек по ходам:** автоматически через случайный интервал один, два или три полных хода; счётчик виден в шапке партии; после перезарядки интервал бросается заново.
- **Постройка в окне маркера действия:** вкладка «Постройка» в модалке маркера (фаза «Действия»).
- **ADR 012:** постройка по маркеру действия, без фазы производства.

### Fixed

- **Выбывший в бою:** не нужно подтверждать готовность, продолжение или выбор потерь — бой с оставшимся флотом сдавшихся идёт без их участия.
- **Наблюдатели боя:** броски восстанавливаются из `pendingCombat.roundState`; `lastCombatResult` не сбрасывается до следующего боя.
- **Поддержка в prep:** третья сторона с кораблями поддержки обязана подтвердить выбор до старта отсчёта.
- **Таблица кораблей в справке:** эсминец 1d4, крейсер 2d6 (как на сервере).
- **Подсветка хода:** reachable — magenta, destination — amber (не сливается с зелёным контролем).
- **Счётчик перезарядки ресурсов:** крупный баннер «До перезарядки ресурсов — N ходов» в блоке событий, в начале партии и при объявлении карты события.
- **Счётчик перезарядки в мультиплеере:** сервер снова отдаёт `resourceRechargeTurnsRemaining` в observation — у всех игроков одно значение.
- **Бросок интервала перезарядки:** только при старте партии и после автоперезарядки в конце хода; в лобби и при нормализации сейва случайный бросок не делается.

### Changed

- **Деплой:** Amvera синхронизирована с GitHub `main`; агентам не пушить в remote `amvera` (`harness/README.md`, `docs/cicd-deploy-policy.md`).
- **Эсминец:** цена уничтожения 4→3 — в дуэли эсминец против эсминца (1d4) максимальная разница кубиков снова может уничтожить противника.
- **Цикл хода:** события → планирование → действия (фаза «Производство» убрана).
- **Постройка:** по маркеру действия в фазе «Действия»; маркеры производства отключены.
- **Интерфейс партии:** убраны элементы, предупреждения и подсказки про маркеры производства (карта, боковая панель, справка, уведомления о фазе).
- **Колода событий:** убраны «Авария на производстве», «Нормирование производства» и «Всё для фронта»; осталось 9 типов карт.
- **Эсминец:** захват нейтральных клеток при объявлении контроля; в бою 1d4 (крейсер — 2d6).
- **Маркеры действия:** старт при одном центре власти — четыре (формула: три плюс число центров).
- **Объявление контроля:** после фазы «Действия», не в производстве.

- **Деплой на Amvera:** `amvera.yaml`, инструкция `docs/deploy-amvera.md` (сборка по `Dockerfile`, push в git Amvera).
- **Деплой на Railway:** `Dockerfile`, `railway.toml`, инструкция `docs/deploy-railway.md`; один контейнер отдаёт клиент и API `/api/*`; скрипты `build:deploy` и `start`.
- **Сводка региона на карте:** при наведении на клетку региона или по правому клику — число клеток, фишки ресурсов, активные фишки, маркеры производства и прочее.
- **Карта — наведение на цели:** при наведении клетки, с которыми сейчас можно взаимодействовать (куда пойти или поставить, доступные маркеры, клетки планирования, в редакторе — клетки и «призраки»), слегка светлеют и обводятся; курсор-указатель только на них. При выборе назначения с маркера действия пульсирует текущий корабль на карте; в подсказке — один слот со значком, как в производстве, текст обычного цвета.

- **Главная — меню и галактика:** стартовый экран — крупная надпись «Галактика Андромеда» всегда в одну строку (при «Играть» поднимается вверх, кегль тот же, тихо мерцает) и вертикальное меню по центру. Слоган целиком под названием: «Вооружайся. Договаривайся. Побеждай.» Кнопки: «Играть», редактор карт, патчноуты. «Играть» открывает прежний вход. Ссылка «К меню» не прячется под названием. За меню — яркий снимок соседней галактики с лёгкой вуалью, медленно плавает. Снимок в комнате партии не меняли.

- **Значки музыки:** на главной нет названия пьесы — только значки заглушения, тише и громче, ползунок и число. В комнате подготовки и в шапке партии то же: пауза, перемешать, повтор, заглушить, исключить — значки с подсказкой. Список пьес в панели прокручивается сам, карта и кнопки комнаты не уезжают.

- **Музыка главной и новые пьесы:** на главной крутится тема «Обломки трона» (заглушить и громкость отдельно от саундтрека партии). Если вкладка не на экране — тема на паузе, как и список пьес в комнате; вернулись и не заглушали — продолжает. В комнате в список добавлены «Шёпот интриг», «Обломки трона», «Тень войны», «Синхрон данных» и «Технологический прорыв» — тот же плеер (перемешать, исключить, громкость, заглушить). Тема главной останавливается при входе в комнату.

- **Полёт кораблей на карте:** после хода значок примерно за половину секунды пролетает к новой клетке (картинка, правила те же). Пока бой не закончен и флот ещё на исходной клетке — без полёта; после разрешения боя пролетает последний отрезок.

- **Космос за картой:** в игровой комнате за полем — снимок звёздного неба; клетки слегка просвечивают, редактор карт без изменений.

- **Фоновая музыка:** на экране партии и в комнате подготовки тихий саундтрек из пяти пьес. Кнопка «Музыка» открывает панель: выбор пьесы, перемешать, повтор списка или одной пьесы, исключить из очереди, громкость, заглушить. По умолчанию список перемешан и крутится целиком. Настройки запоминаются в браузере. Звуки интерфейса выключаются отдельно. Если браузер не дал заиграть сразу — после первого щелчка. Скрытая вкладка ставит на паузу список пьес партии и тему главной; открытая вкладка по умолчанию не заглушается.

- **Патчноуты — человеческий русский:** тексты в `docs/patch-notes/` переписаны для игрока (глоссарий, без сокращений); правила письма — `.cursor/rules/patch-notes.mdc`.

- **Победа и маркеры действия:** большинство центров власти или последний невыбывший игрок; маркеры действия — по одному за каждый контролируемый центр власти, без покупки. См. `docs/decisions/010-victory-am-from-power-centers.md`.

- **Окно объявления события:** при смене хода на экране номер хода, название карты и краткий эффект («Понятно» или щелчок по фону). Карта уже применена; браузер запоминает объявление этой комнаты на этом ходе. Вход посреди хода не повторяет окно. Карточка на боковой панели без изменений.
- **Маркер производства:** снять с карты можно бесплатно (как маркер действия, с подтверждением); дополнительный маркер — не больше одного за игровой ход. См. `docs/decisions/009-production-marker-buy-and-discard.md`.
- **Страница патчноутов:** история и полные тексты из `docs/patch-notes/` на `/patch-notes`; короткое уведомление о свежем патчноуте (без баннера согласия).
- **Патчноуты агента:** после изменений в проекте пишется структурированная заметка в `docs/patch-notes/` (правило `.cursor/rules/patch-notes.mdc`).
- **Без снабжения:** корабли снабжения убраны; оплата и перезарядка только из региона маркера производства; объявление контроля в начале производства (эсминцы не берут нейтральную клетку, рейдят чужой контроль без флота); на тот день запас маркеров — три действия и одно производство, действие до восьми за шесть плюс шесть кредитов и производства; сдача. Бумажную версию для печати не обновляли.
- **Настольный print-and-play:** снимок текущего билда — `docs/tabletop-rules-v3-print.md` и PDF `docs/tabletop/Galaxy-Andromeda-print-and-play.pdf` (правила, карты `duel-2p` / `tts-reference`, колода событий, фишки, маркеры, корабли). Пересборка: `pnpm tabletop:print`.
- **Лобби подготовки:** новая комната не стартует партию сразу. Игроки выбирают слот (позиция + цвет), хост жмёт «Начать игру». После старта маркеры планирования доступны только когда настал ваш ход в уже начатой партии.
- **UI — звуки:** короткий сигнал «ваш ход» и другой — «начало боя/обстрела» (Kenney Interface Sounds, CC0). Кнопка без звука в шапке рядом с «Правила» (`localStorage`: `galaxy-sfx-muted`).
- **Карта `maps/duel-2p.json`:** компактная симметричная дуэль на 2 игрока (23 гекса, 3 центра власти, два стартовых эсминца).
- **UI — справка по правилам:** кнопка «Правила» в шапке игры открывает модалку с лаконичной однозначной выжимкой (победа, карта, корабли/цифры, бой, обстрел, производство, фазы, события). Контекстная подсказка хода остаётся в правой панели.
- **UI — подсказка новичкам:** у кнопки «Правила» всплывающая подсказка «Не знаете что делать?…»; можно скрыть крестиком (или открытием правил) — запоминается в `localStorage`.
- **Баг-репорт:** кнопка «Баг» в шапке игры — описание + опциональный скриншот; `POST /bug-reports` сохраняет в `.bug-reports/` на сервере, автоудаление через 60 дней.

### Changed

- **Колода событий:** убраны «Активация диверсантов» и «Народное пожертвование» (переворот всех фишек). В сейвах заменяются на «Среди звёзд лишь пустота».
- **Производство — клетка маркера:** корабли ставятся только на клетку исполняемого маркера производства, не на другие клетки региона.

- **Крейсер в прямом бою:** на клетке боя бросает **2d4** (раньше 2d6). Поддержка с дистанции по-прежнему 1d4. Эсминец без изменений (1d6, цена уничтожения 4). Два эсминца против одного крейсера без поддержки выигрывают раунд примерно в семи случаях из десяти (~77%, если ничьи перебрасывать).

- **Плеер саундтрека в комнате:** в панели «Музыка» текущую пьесу можно поставить на паузу и перемотать полоской времени. «Заглушить» только выключает звук, время пьесы идёт дальше. Ползунок громкости спрятан за кнопкой «Громкость». Скрытая вкладка по-прежнему ставит музыку на паузу сама.

- **Окно итога боя и карта:** после раунда крупно видно победу, поражение или ничью, броски и суммы без повторов, отдельной строкой — кто сейчас выбирает потери или решает продолжить бой. На карте клетка боя пульсирует, входящие корабли подсвечены, погибшие в раунде коротко остаются призраками. Кнопки «продолжить» и «отступить» по-прежнему сразу после закрытия итога, без обновления страницы.

- **Контроль при входе:** если ваши корабли заходят на клетку под контролем другого игрока, контроль сразу становится вашим (в том числе эсминцем), чужой маркер производства снимается. Бой по-прежнему только при вражеских кораблях на клетке. Нейтральную клетку вход не красит: её объявляют в начале производства кораблём, который не эсминец. То же правило входа действует при отступлении и когда атакующий входит на клетку боя после ухода защитника. Обстрел клетку не захватывает.

- **Производство — подтверждение расстановки:** когда все корабли заявки стоят на клетках, игра не строит сразу. На карте видны будущие значки, они коротко увеличиваются и уменьшаются; окно спрашивает «Разместить эти корабли?». «Да» создаёт корабли. «Назад к расстановке» возвращает к черновику клеток, корабли ещё не появляются. Пока игрок кликает клетки, полоска заявки показывает, какие корабли уже стоят и какие ещё нет. Перезарядка фишек и покупка маркера производства без кораблей по-прежнему без этого вопроса.

- **Маркеры действия:** доступно два плюс число ваших центров власти (на старте три). Лимит пересчитывается только в начале хода; потеря или захват центра в середине хода сразу не меняет число маркеров. См. `docs/decisions/011-action-markers-two-plus-centers.md`.
- **Экспорт карты:** скачанный файл называется по **названию** карты, а не по служебному коду. Запрещённые в имени файла символы заменяются; пустое название — запасной вариант по коду. Внутри файла код карты не менялся.

- **Правила — победа:** условие «четыре связных региона не меньше чем по семь клеток» снято. Остались строго больше половины всех центров власти на карте и последний невыбывший игрок (включая сдачу).
- **Правила — маркеры действия:** сколько центров власти вы контролируете, столько маркеров действия; покупка в производстве убрана. Ноль центров — ноль маркеров. Потеря центра снимает лишние маркеры с карты. Событие «Авария на производстве» запрещает только покупку маркеров производства.
- **Окно производства:** плитка покупки маркера действия убрана.
- **Правила — маркеры производства:** постоянный потолок «один маркер на регион» снят; в одном регионе можно несколько. Карта «Нормирование производства» (раньше «Сверхурочные») на этот ход **запрещает** второй маркер производства в регионе; лишние возвращаются в неиспользованный запас. Фишки кредитов и производства не затронуты. Бумажную версию для печати не меняли.
- **Окно производства:** остаток кредитов и производства после текущей заявки вынесен в центр шапки крупным кеглем; плитки покупок по-прежнему на одном экране.
- **Окно производства:** кнопка «Снять маркер» (бесплатно, без фишек); покупка дополнительного маркера производства отключается после одной покупки за ход. Кнопка в шапке партии ведёт себя так же.
- **Окно производства:** все покупки фазы (корабли, маркер действия, маркер производства, перезарядка) на одном экране без шага «выберите действие» и без прятания опций за прокруткой. Кнопка «Купить маркер производства» в шапке остаётся.
- **Полосы прокрутки:** тонкие контрастные полосы на тёмном фоне во всём клиенте.
- **События — автоприменение:** карта хода вытягивается и применяется сама в конце производства; игроки не подтверждают. Фаза событий не интерактивна, сразу планирование. Старое действие «применить событие» оставлено для совместимости со старыми клиентами.
- **Крейсер — регион:** постройка от **пяти** клеток (было восемь). Цены в таблице кораблей не менялись.
- **Правила — только русский:** игровая справка, `docs/rulebook.md` и `docs/tabletop-rules-v2-balance-bf.md` без англицизмов в формулировках для игрока (кредиты, центры власти, пропуск приоритета, постройка/перезарядка и т.д.). В справке — шрифт Manrope, крупнее кегль и мягче межстрочный интервал.
- **Правила — фазы хода:** в справке и `rulebook.md` добавлено чёткое описание, что происходит в каждой фазе (События, Планирование, Действия, Производство).
- **События — колода:** вытягивание из перемешанной колоды (`eventDeck` в snapshot); при опустошении — новая перетасовка. Жёсткие карты (1 копия), средние (2), мягкие/полезные (2–3). См. ADR 006.
- **Корабль `hyper`:** отображаемое имя «Гиперпространственное орудие» (вместо «Г.О.» / «генератор обороны»).
- **Корабль `supply`:** отображаемое имя «Корабль снабжения» (вместо «Снабжение»).
- **Баланс B+F:** `destroyCost` эсминца 3→4; все кубики поддержки (крейсер 1, линкор 2, Г.О. 3) теперь d4 вместо d6. Число кубиков, дальность и `combatDice` на гексе не менялись. Добавлена отслеживаемая версия настольных правил `tabletop-rules-v2-balance-bf.md`.
- **UI — маркеры производства:** обводка кольца на карте сплошная (без пунктира).
- **UI — tooltip клетки:** при наведении на гекс на карте (задержка 1 с) — компактная подсказка: владелец, центр власти, токен ресурса, флот по игрокам; корабли — списком с SVG-глифами и множественным числом.
- **UI — стрелки приказа:** превью хода на карте исходит от иконки корабля (по `shipId`), а не из центра гекса.
- **UI — BattleModal:** колонки, суммы, броски и поддержка окрашены цветами реальных игроков (`snapshot.players`), а не фиксированными «атака/защита»; корабли поддержки — цветом владельца.
- **UI — подсветка хода и границ:** пульсация интерактивных элементов (кнопка фазы, маркеры на карте, skip в бою) заметнее — быстрее цикл, сильнее glow/opacity; границы территорий ярче и уже (inset 0.32, gradient stops 0.88→0.36, perimeter opacity 0.98).
- **Priority skip — порядок:** объявлять можно только префикс цепочки `destructionPriority` среди типов противника в бою; пропуск последнего присутствующего типа запрещён (бессмысленен). UI кликает skip по порядку; снятие каскадно снимает следующие. +1 `destroyCost` без изменений.
- **Prep UI — priority skip:** подсказка о выборе пропуска, мигание доступного типа, тусклые недоступные, список типов «при победе можно уничтожать», прогноз перевеса кубиков (ожидание + %).
- **Движение:** reachable / валидация хода — BFS по существующим гексам; через дыры карты («пустые» клетки) лететь нельзя. Через клетки с вражескими кораблями/контролем путь тоже не идёт (бой — только конечная клетка). Поддержку пока не меняли.
- **Событие «Местная самооборона»:** явно: запрет только на **вход движением**; отступление из боя на клетку с фишкой/центром власти разрешено (rulebook, справка, текст карты).
- **Поддержка третьей стороны:** в `BattleModal` добавлена явная кнопка «Не поддерживать» — наблюдатель с кораблями в радиусе может отказаться от участия (сервер уже поддерживал `supportSide: null`).

### Fixed

- **Редактор карт — камера:** при рисовании клеток карта больше не отдаляется сама. В нижнем управлении камерой кнопка «Подгонять»: выключена по умолчанию — зум и сдвиг остаются как вы их поставили; включите, если хотите, чтобы кадр сам охватывал всю карту. Плюс, минус, процент и сброс вида не менялись. В партии кадр по-прежнему показывает всю карту.

- **Редактор карт — симметрия:** зеркало для двух игроков теперь умеет все шесть осей. «Через центры гексов» и «через границы» больше не делают одно и то же. Горизонталь через центры работает, когда карта показана **углом вверх**; гранью вверх горизонталь идёт через границы, и панель это объясняет.

- **Бой — продолжить или отступить без обновления страницы:** после раунда боя кнопки «продолжить» и «отступить» больше не пропадают, если игрок уже закрыл окно итога. Очередь считается по роли в бою (сначала атакующий, затем защитник), а не по тому, чей сейчас ход на карте. После подтверждения потерь тот же раунд не открывает итог заново и не оставляет пустой экран до обновления страницы.

- **Лобби не открывалось:** после правки полёта кораблей главная страница не грузилась; лишняя закрывающая скобка в клиенте убрана, лобби снова открывается.
- **Лобби — вход в начале партии:** второй игрок больше не попадает в уже идущее планирование чужого хода. Сначала комната подготовки, старт по команде хоста.
- **Бой UI — итоги не исчезают сами:** окно результата боя/обстрела остаётся, пока игрок не нажмёт «Закрыть»; сверка UI больше не срывает просмотр ради баннера continue/retreat. Итог виден всем клиентам; после закрытия на баннере чужого боя — «Показать итог».
- **Захват клетки:** вход на клетку под контролем другого игрока без боевого флота сразу передаёт контроль входящему и снимает чужой маркер производства. То же при победе в бою движением и при отступлении на такую клетку.
- **Действия — снятие маркера:** снять маркер действия в фазе «Действия» засчитывается как ход (`actionMarkerResolvedThisTurn`); второй маркер в том же круге исполнить нельзя. То же для снятия маркера производства в «Производстве».
- **Лобби — цвет слота:** пикер показывает названия цветов (`PLAYER_LABELS`); кнопка входа — «Войти как {ник} · {цвет}».
- **UI — шапка vs сайдбар:** высота шапки (`.hud-top`) измеряется `ResizeObserver` без петли `min-height` ↔ CSS-var; сайдбар не перекрывается шапкой.
- **UI — ProductionModal:** `max-height` + скролл body, футер «Разместить» всегда доступен.
- **Dev/tuna — HMR:** `pnpm dev:tunnel` / `NUXT_HMR_TUNNEL=1` → wss/443; при Mixed Content WS — баннер с предложением обновить страницу.
- **Бой — щит:** поглощает урон **проигравшей** стороны (атака или защита); в prep видны щиты обеих сторон с ролями; после бросков сначала итог, победитель сам открывает выбор уничтожения; `combat.auto-resolve` логирует `loserId` / `shieldAbsorbed`.
- **Бой — триггер:** бой только при вражеском корабле (пустая клетка, в том числе под чужим контролем, — не бой). Обстрел по-прежнему по кораблям или чужому контролю. Вход на клетку под контролем другого игрока сразу передаёт контроль.
- **Победа — центры власти:** большинство считается от **всех** `isPowerCenter` на карте (не только занятых); термин «энергоцентр» заменён на «центр власти».
- **Бой UI — рассинхрон:** клиент сверяет `pendingCombat` с видимым UI (prep / уничтожение / continue-retreat); при расхождении — баннер «Рассинхрон с сервером», авто-recovery и resync.
- **Бой UI — soft-lock continue/retreat:** после закрытия итогов модалка больше не переоткрывается поверх баннера; dismiss устойчив к poll; кнопки «Продолжить/Отступить» дублируются в модалке; новый раунд сбрасывает dismiss только при новом fingerprint.
- **Движение через врагов:** путь BFS не проходит через клетки с вражескими кораблями/контролем; на такую клетку можно только войти конечным шагом (бой).
- **Фаза действий — ранний production:** `skipPlayersWithoutPhaseActions` при оставшихся маркерах заворачивает круг (`остались маркеры`), а не закрывает фазу.
- **UI — снятие маркера действия:** в модалке маркера кнопка «Снять маркер без действия»; текст блокировки хода указывает число оставшихся маркеров.
- **Бой — раунд 2+:** `continue-combat` больше не теряет `combatResult` при завершении боя в том же шаге; иначе сервер оставлял `lastCombatResult` прошлого раунда (флот до уничтожений). После уничтожения снова показывается итог, затем баннер continue/retreat.
- **Бой — после выбора потерь:** модалка больше не переигрывает броски того же раунда со «старым» составом флота (ключ анимации считается только по броскам); у подтвердившего уничтожение модалка закрывается сразу, и баннер «продолжить/отступить» появляется немедленно. Устранена гонка, из-за которой закрытый итог боя открывался заново.

Решение attacker → defender теперь показывает допустимые клетки отступления и передаёт `retreatTo`; отступившие корабли действительно перемещаются. При захвате клетки удаляется маркер действия защитника.

Старые сохранения мигрируют через `migrateLegacyPendingCombat`. Клиент и сервер читают одну и ту же фазу — меньше рассинхронов экрана боя.
- **Бой:** неучастник с кораблями поддержки в `fireRange` выбирает в prep сторону помощи, остальные наблюдают без ready/skip UI; после раунда решение принимается в порядке attacker → defender; следующий раунд запускается только после двух «Продолжить», а оба участника могут отступить (кроме «Стоять насмерть!»). Выбор уничтожения в модалке динамически блокирует корабли, не помещающиеся в остаток бюджета, и показывает фактическую цену с учётом событий и priority skip.
- **Производство и очередь хода:** активный игрок обязан использовать, перезарядить или снять свой маркер производства перед передачей хода; игроки без доступного действия в Planning/Actions/Production пропускаются автоматически. В `ProductionModal` кредиты и производство отмечены цветными символами `₡` и `⚙`.

- **Г.О. fireRange:** min 2 / max 3 (не соседняя клетка)

### Fixed

- **Бой — вход и маркер после wipe:** если бой завершился в follow-up (полный wipe), атакующие теперь реально входят на клетку; маркер действия снимается, когда на клетке не осталось кораблей его владельца (не только «маркер защитника при победе атаки»).

После раунда модалка закрывается; атакующий видит баннер с выбором, защитник ждёт с понятным текстом, затем получает такой же UI. Клетки отступления подсвечены на карте (клик или кнопка); наведение на кнопку подсвечивает клетку ярче.
- **Бой — выбор уничтожения по типу:** `validateDestructionSelection` больше не сравнивает экземпляры одного типа по порядку id («Эсминец раньше Эсминец»). Приоритет действует между типами; среди эсминцев/крейсеров можно выбрать любой экземпляр.
- **Бой — C1/C2 (раунд 2+):** `continuePendingCombat` передаёт `pending.attackerId` (а не `playerId` защитника) и сохраняет `movementFrom`/`movementPlans` в `roundState`; после выбора уничтожения `roundNumber` увеличивается.

Итог раунда теперь показывает суммы, разницу, щиты, уничтожения и статус продолжения без ошибочного текста о поражении при ничьей.
- **Лимит маркеров производства:** первый маркер базовый; второй разблокируют 3, третий — 5 отдельных контролируемых регионов по ≥ 4 клетки. Регион остаётся связной контролируемой территорией; ставить маркер можно только в valid region от 3 клеток.
- **Мультиплеер — отстающий клиент:** polling больше не прекращается, если его тик пришёлся на собственное действие; цикл защищён generation-токеном от позднего ответа после unmount/restart и опрашивает state каждые 750 мс (250 мс при активном бое).
- **Перезарядка производства:** теперь поднимает все перевёрнутые ресурсные фишки в цепочке снабжения — Credits и Production; модалка и валидация учитывают оба типа.
- **Мультиплеер — отклонённые действия:** клиент показывает текст HTTP 400, сразу повторно получает authoritative observation и не оставляет устаревший экран; в планировании локально блокируется попытка поставить маркер производства вне региона от 3 клеток.
- **Мультиплеер — баннер синхронизации:** кнопка «Обновить страницу» вызывает защищённый `reloadPage()` из script setup, а не обращается к `window` из Vue-template.
- **Мультиплеер — восстановление sync:** клиент отслеживает monotonic `observationRevision`, три подряд неудачных poll и ответ действия без роста revision; после сигнала делает до трёх немедленных повторных запросов с backoff. Если authoritative state не удалось подтвердить, показывается постоянное предупреждение с действиями «Синхронизировать» и «Обновить страницу».
- **Мультиплеер — подготовка к бою:** API-клиент принудительно отправляет запросы с телом как `POST` и запрещает автоматические redirect, которые могли превратить `POST /action` в `GET`; ошибочный `GET /action` теперь возвращает 405 с понятной причиной.
- **Обстрел — защитник не бросает кубики (PDF):** `buildBombardmentPreview` обнуляет combat/support защитника; `rollCombatRound` при `trigger: bombardment` бросает только атакующего (`defenderTotal = 0`, winner всегда attacker); очки уничтожения = сумма обстрела; UI `BattleModal` / `CombatPreviewPanel` не показывают бросок защитника
- **Priority skip в подготовке к бою:** skip объявляется без оплаты; чекбоксы в `BattleModal` всегда доступны для типов на своей стороне
- **Мультиплеер — синхронизация состояния:** сервер как единственный источник истины — `buildObservation` передаёт все поля snapshot (включая явные `null` для очищенного состояния); `gameSnapshotFromObservation` больше не сохраняет устаревшие `turnEvent`, `gameOver`, `eventLog`, `pendingCombat`; `observationRevision` на сервере; клиент отбрасывает устаревшие ответы и синхронизирует `lastCombatResult` (включая очистку); polling 400ms на любой `pendingCombat`; `buildCombatPreviewFromPending` работает для `awaitingDestruction`/`roundState` — защитник видит модалку после боя
- **Мультиплеер — countdown боя:** защитник больше не зависает на «Бой через…» — `pendingCombat` не сохраняется локально после очистки сервером; `lastCombatResult` повторяется в observation до следующего действия; resync по окончании countdown с повторными попытками
- **Мультиплеер — анимация бросков:** polling больше не сбрасывает фазу «кубики крутятся» — `combatResolutionFingerprint` + guard в `BattleModal`; щитоносцы видны в превью и модалке боя с подписью «Щит: поглощает до N»
